## Ⅰ. 문제의 성격 — 왜 자율실험실에서 새로 설계해야 하나

기존 연구실 안전·기록 관리는 **"연구자가 보고 판단한다"** 를 전제한다. 자율실험실은 **그 전제가 무너진다**.

| | 기존 실험실 | 자율실험실 |
|---|---|---|
| 위험 판단 주체 | 연구자(실행 직전 육안·경험) | **없음** — AI가 조건을 정하고 로봇이 실행 |
| 기록 주체 | 연구자(실험노트) | 시스템 자동 기록 |
| 실험 설계 | 사람이 사전 확정 | **실행 중 AI가 변경** |
| 위험 발생 시점 | 실행 시점 | **AI가 조건을 제안한 시점** |

> **결론** : 스크리닝은 사람의 눈이 아니라 **주문 API·프로토콜 실행기 같은 코드 레벨의 관문**에 들어가야 하고, 이력은 **AI의 판단 과정까지** 남겨야 한다.

**핵심 설계 원칙** — 이력 추적과 스크리닝은 **하나의 시스템의 앞뒤**다. 스크리닝은 *실행 전 차단*, 이력은 *실행 후 증명*이며, **스크리닝 결과(통과·차단·예외승인) 자체가 이력에 기록**되어야 사후 감사가 성립한다. 둘을 별개 시스템으로 만들면 **우회가 기록에 남지 않는다.**

## Ⅱ. 실험 이력 추적 — How

### 2-1. 기준은 이미 있다: ALCOA+ 와 감사추적(audit trail)

- **ALCOA+** : 기록은 **귀속가능(Attributable)·판독가능(Legible)·동시기록(Contemporaneous)·원본(Original)·정확(Accurate)** + **완전·일관·영속·이용가능**해야 한다. FDA가 2018년 데이터 무결성 Q&A에서 데이터 무결성을 ALCOA에 명시적으로 결부
- **감사추적 요건**(21 CFR Part 11) : **안전한, 컴퓨터가 생성한, 시각이 기록된 감사추적**으로 전자기록의 생성·수정·삭제 행위와 그 일시를 기록. **누가·무엇을·언제·왜** 변경했는지 포착
- 참고 : 데이터 무결성은 규제기관 실사의 최대 지적사항 — FDA 경고서한의 상당수가 데이터 거버넌스 실패를 지적

> **시사점** : 새 기준을 만들 필요가 없다. **제약·GxP 분야에서 검증된 ALCOA+·감사추적 요건을 자율실험실로 이식**하면 된다.

### 2-2. 무엇을 기록할 것인가 — 5개 계층

기존 ELN/LIMS는 ①②④⑤만 다룬다. **③ AI 계층이 자율실험실의 공백**이다.

| 계층 | 기록 항목 | 비고 |
|---|---|---|
| ① **물질·시료** | 시약 로트·유효기간, 시료 ID·계보(분주·희석 이력), 폐기 이력 | 바코드·RFID 연계 |
| ② **장비·조작** | 장비 ID·펌웨어 버전, 검·교정 이력, 실제 수행 파라미터(설정값이 아닌 **실측값**), 오류·재시도 | 표준 인터페이스(SiLA·LADS)에서 자동 수집 |
| ③ **AI 의사결정** ★ | **모델 ID·버전·해시**, 학습 데이터 스냅샷, **제안된 후보군 전체**(채택되지 않은 것 포함), 선택 근거·획득함수 값, 랜덤시드, **사람의 개입·중단 이력** | **여기가 핵심 공백** |
| ④ **데이터·결과** | 원시 데이터(가공 전), 처리 파이프라인 버전, 파생 결과와의 연결 | AnIML·Allotrope의 감사추적 기능 활용 |
| ⑤ **사람·권한** | 승인자, 접근 권한 변경, 예외 승인 사유 | 전자서명 |

**③이 왜 중요한가** — SDL에서 "왜 이 실험을 했는가"의 답은 사람이 아니라 모델이다. **모델 버전과 제안 후보군을 남기지 않으면 실험을 재현할 수 없고, 결과를 방어할 수도 없다.** 채택되지 않은 후보까지 남겨야 선택 편향을 사후에 검증할 수 있다.

### 2-3. 어떻게 구현할 것인가

1. **자동 수집** — 표준 인터페이스(SiLA 2·OPC UA LADS)로 장비에서 ②를 자동 수집. **사람이 입력하는 기록은 ALCOA+의 '동시기록'을 만족하지 못한다.**
2. **표준 형식** — **AnIML**(감사추적·GxP 대응 내장), **Allotrope ADF**(측정 조건의 의미론적 기술)를 데이터 형식으로 채택. 국내 독자 포맷을 만들지 않는다.
3. **무결성 보장** — 기록의 **해시 체인 + 신뢰 타임스탬프 + 변경불가 저장(WORM)**. 블록체인까지 갈 필요는 없으며, 해시 체인과 시점확인 서비스로 충분하다.
4. **보존·이관** — 보존기간을 사업 협약 단계에서 규정하고, **DataON** 등 국가 플랫폼과 연계
5. **적합성 확인** — 이력 체계를 **KOLAS(ISO/IEC 17025) 적용지침**의 요구사항으로 편입 → 자율실험실 산출 데이터가 시험성적서로 통용되는 근거

## Ⅲ. 이중용도 사전 스크리닝 — How

### 3-1. 3중 관문 구조

위험은 세 지점에서 들어온다. **한 곳만 막으면 나머지로 우회된다.**

| 관문 | 대상 | 차단 시점 |
|---|---|---|
| **① 물질·서열 조달** | 시약 주문, 유전자 합성 발주 | 발주 API 호출 시 |
| **② 실험 계획(프로토콜)** | 합성 경로, 반응 조건 조합 | 프로토콜 컴파일·실행 직전 |
| **③ AI 모델** | 목적함수 역전, 위험 후보 생성 | 모델 설계·운영 시 |

### 3-2. 관문 ① 물질·서열 조달 — 도구가 이미 무료로 존재

**생물(핵산 서열)**

- **IGSC 조화 스크리닝 프로토콜(Harmonized Screening Protocol)** : 유전자합성 기업 컨소시엄이 회원사에 준수를 의무화. **자체 큐레이션한 제한 병원체 데이터베이스(Restricted Pathogen Database)** 대조 심사
- **Common Mechanism** : **무료·배포형·오픈소스·자동화된 DNA 합성 스크리닝 소프트웨어**. NTI\|bio가 2024년 **IBBIS**를 상설 운영주체로 출범시켜 관리
- **SecureDNA** : 서열 스크리닝 도구
- **2025.10 기준 IBBIS·SecureDNA 모두 포털을 운영**하여 합성 공급자가 **블라인드 테스트를 받고 pass/fail 확인서(attestation)** 를 발급받을 수 있음
- **마찰 최소화 설계** : IBBIS는 **'신규 고객 양식'과 'SOC(우려서열) 주문 양식'의 2단 구조**를 두어, **우려서열을 주문하지 않는 대다수 고객은 최소한의 절차만** 거치게 함

**미국 제도 동향(참고)**

- **OSTP 「핵산 합성 스크리닝 프레임워크」('24.4)** : 합성 핵산과 **이를 합성할 수 있는 벤치탑 장비**를 **프레임워크를 준수하는 공급자·제조사로부터만 조달**하도록 요구
- **2026.10.13부터 스크리닝 윈도우를 50뉴클레오타이드 단위로 축소**(민감도 강화)
- **행정명령 14292**('25.5)로 프레임워크 개정 지시 → **'26.8월 기준 개정본은 아직 미공표**(ASPR는 새 프레임워크 공개 시 갱신 예정이라고 안내)
- 연방자금을 받지 않는 연구에 대해서도 스크리닝 적용 범위를 넓히는 전략 수립 지시

**화학·기타 물질 — 국내법이 이미 근거를 제공**

- **「화학무기·생물무기의 금지와 특정화학물질·생물작용제 등의 제조·수출입 규제 등에 관한 법률」** : 화학무기 제조에 이용 가능한 물질을 **1종·2종·3종 특정화학물질**로 분류하고, **제조·가공·소비자에게 매년 계획 및 실적 신고 의무** 부과
- 이 외 **전략물자 수출입 규제, 고위험병원체·생물작용제 관리, 화학물질관리법상 사고대비물질·제한금지물질** 체계 존재

> **핵심 판단** : **국내 독자 스크리닝 DB를 만들려 하면 실패한다.** 병원체·서열 데이터베이스의 큐레이션은 국제 컨소시엄 수준의 지속 투자가 필요하다. **Common Mechanism 같은 오픈소스 도구를 채택하고, 국내법상 규제물질 목록(특정화학물질 1~3종 등)을 로컬 규칙으로 추가**하는 구조가 옳다.

### 3-3. 관문 ② 실험 계획(프로토콜) 스크리닝

- 정책 논의의 방향 : **클라우드랩·자율실험실은 핵산 기질뿐 아니라 "프로토콜"까지 스크리닝**해야 한다는 제안이 제기되어 있으며, 미국 OSTP가 **AI 기반 자동화 실험실용 스크리닝 지침**을 범부처로 개발 중
- 구현 지점 : **프로토콜이 장비 명령으로 변환되는 순간**(컴파일·스케줄링 단계)에 규칙 검사를 삽입 — 개별 시약은 무해해도 **조합·순서가 위험한 경우**를 잡아내야 하기 때문
- 검사 항목(예) : 규제물질 전구체의 조합, 특정 반응 유형, 규모(스케일업), 비정상적 반복 합성

### 3-4. 관문 ③ AI 모델 — 목적함수 역전 방지

- **근거 사례** : Urbina 등(Nature Machine Intelligence, 2022)은 상용 신약탐색 ML 모델에서 **독성에 벌점을 주던 로직을 보상으로 뒤집자, 6시간 만에 4만 개의 독성 후보 분자**를 생성했고 여기에 **VX급 신경작용제**가 포함되었다
- 즉 **위험은 새 모델이 아니라 기존 모델의 부호 하나에서 나온다**
- 대응 : 목적함수·보상 설정에 대한 **검토 절차**, 위험 후보 생성 시 **자동 플래그·기록**, 모델 접근권한 관리. Ⅱ-2의 **③ AI 의사결정 이력**이 그대로 이 통제의 근거가 된다

### 3-5. 운영 원칙 — 과잉규제 회피

1. **위험 등급별 차등** — IBBIS의 2단 양식처럼 **대다수 실험은 무마찰 통과**, 우려물질·서열에만 심층 절차
2. **오탐(false positive) 처리 경로** — 자동 차단 시 **사람 검토로 넘기는 창구**를 반드시 둔다. 없으면 연구자가 시스템을 우회한다
3. **차단 자체를 기록** — 통과·차단·예외승인 전부 Ⅱ의 이력에 남긴다

## Ⅳ. 〈자체 제안〉 국내 적용 설계

### 4-1. 3단계 로드맵

| 단계 | 이력 추적 | 이중용도 스크리닝 |
|---|---|---|
| **1단계 (~1년)** 지침 | 「자율실험 데이터 기록·보존 가이드라인」 제정 — ALCOA+ 기반 5개 계층 기록항목 규정 | 국가사업 자율실험실 대상 **스크리닝 의무 협약조항** 신설. 국제 오픈소스 도구(Common Mechanism 등) 도입 타당성 검토 |
| **2단계 (1~3년)** 구현 | 표준 인터페이스로 **자동 수집** 구현, AnIML·Allotrope 채택, 해시체인·타임스탬프 적용 | **국가 스크리닝 게이트웨이** 구축 — 국제 도구 + **국내 규제물질 목록(특정화학물질 1~3종, 고위험병원체 등)** 결합. 프로토콜 단계 검사 시범 적용 |
| **3단계 (3년~)** 제도화 | **KOLAS(ISO/IEC 17025) 적용지침**에 이력 요구사항 편입 → 산출 데이터의 성적서 통용 | 자율실험 서비스 사업자의 **스크리닝 이행을 인증 요건화**. 국제 프레임워크(OSTP 등) 개정 동향에 정합 |

### 4-2. 소관 및 연계

- **이력 추적** : 과기정통부(자율실험실 사업) + 국가기술표준원·KOLAS(적합성) + KISTI(DataON 보존)
- **스크리닝** : 산업부(특정화학물질·전략물자), 질병관리청(고위험병원체), 과기정통부(연구실 안전) → **부처 간 창구 단일화가 최대 난제**. 자율실험실 협의체에 **생물·화학 안전 소분과** 신설 권고
- **표준·인증 트랙과 연동** : 이력 요구사항은 앞서 제안한 **자율화 수준(Level) 표준**의 상위 등급 요건으로 편입 — 자율성이 높을수록 기록 요구가 강해지는 구조

## Ⅴ. 〈자체 제안〉 본문 문안(안)

**□ (신뢰성 확보) 실험 산출물의 신뢰성 확보를 위해 실험 이력 추적 체계를 구축하고, 이중용도(dual-use) 가능 위험물질 등에 대한 사전 스크리닝 체계를 마련**

※ **(이력 추적)** 제약·GxP 분야에서 확립된 **ALCOA+ 원칙과 감사추적(audit trail) 요건**을 자율실험 환경에 이식하되, **AI 의사결정 이력(모델 버전·제안 후보군·선택 근거·인적 개입)** 을 기록 대상에 포함 — 자율실험에서는 실험 사유가 사람이 아닌 모델에 있어 **이를 남기지 않으면 재현·검증이 불가**
※ **(자동 수집)** 표준 인터페이스(SiLA 2·OPC UA LADS)를 통해 장비 실측 파라미터를 **자동 기록**하고, **AnIML·Allotrope 등 국제 데이터 형식**을 채택. 해시체인·신뢰 타임스탬프로 무결성 보장
※ **(사전 스크리닝)** **물질·서열 조달 / 실험 프로토콜 / AI 모델**의 **3개 지점에 스크리닝 관문**을 설치. 자율실험은 실행 직전 연구자의 육안 판단이 없으므로 **발주 API·프로토콜 실행 단계 등 코드 수준에 관문을 내장**
※ **(국제 도구 활용)** 서열 스크리닝은 **Common Mechanism(IBBIS 운영, 무료·오픈소스)** 등 국제 도구를 채택하고, **국내 규제물질 목록**(「화학무기·생물무기 금지법」상 특정화학물질 1~3종, 고위험병원체 등)을 결합. 국내 독자 데이터베이스 구축은 지양
※ **(과잉규제 방지)** 위험 등급별 차등 적용으로 **대다수 실험은 무마찰 통과**시키고, 자동 차단 건에 대한 **사람 검토 경로**를 반드시 병행. **통과·차단·예외승인 이력을 모두 기록**하여 사후 감사 가능성 확보

### 5-1. 당구장 1개 축약안

지면이 ※ 하나뿐일 때 사용.

> ※ 감사추적(ALCOA+) 요건과 국제 데이터 형식을 준용하되, 자율실험 특성을 반영해 **AI 의사결정 이력(모델 버전·제안 후보군·선택 근거)** 을 기록 대상에 포함하고, 스크리닝은 실행 직전 연구자 확인이 없는 점을 고려해 **발주·프로토콜 실행 등 코드 단계에 내장** — 국제 오픈소스 도구에 **국내 규제물질 목록**을 결합하고 위험 등급별로 차등 적용

**더 짧게**

> ※ 감사추적(ALCOA+) 기반으로 **장비 실측값과 AI 의사결정 이력을 자동 기록**하고, 스크리닝은 **발주·프로토콜 단계에 내장**하여 국제 오픈소스 도구에 국내 규제물질 목록을 결합·적용(위험 등급별 차등)

축약 시 버리는 것 : 3중 관문의 'AI 모델' 지점, 오탐에 대한 사람 검토 경로, 무결성 보장 수단(해시체인·타임스탬프). 별도 설명 기회가 있으면 **사람 검토 경로**를 먼저 되살릴 것 — 없으면 현장에서 시스템을 우회한다.

## Ⅵ. 유의사항

1. **이력과 스크리닝을 별개 시스템으로 만들지 말 것** — 스크리닝 우회가 기록에 남지 않으면 체계 전체가 무력화된다.
2. **국내 독자 스크리닝 DB 구축은 지양** — 병원체·서열 DB 큐레이션은 국제 컨소시엄 수준의 지속 투자가 필요하다.
3. **오탐 처리 경로 없는 자동 차단은 우회를 부른다** — 사람 검토 창구가 제도의 필수 구성요소다.
4. **미국 프레임워크는 개정 중** — EO 14292에 따른 개정본이 '26.8월 기준 미공표이므로, 국내 기준을 미국 현행 프레임워크에 고정하면 곧 어긋난다. **원칙 중심으로 쓰고 세부는 지침에 위임**할 것.

## Ⅶ. 한계

- **국내 규정 확인 부족** : 특정화학물질 1~3종의 구체적 목록·신고 절차, 고위험병원체 관리 규정, 연구실안전법상 유해인자 관리와의 중복 여부는 **원문 확인이 필요**하다.
- **화학 분야 스크리닝 도구** : 생물(서열) 분야는 Common Mechanism·SecureDNA 등 도구가 확인되었으나, **화학 합성 프로토콜용 상용·공개 스크리닝 도구는 이번 조사에서 확인하지 못했다.** 관문 ②는 현재 규칙 기반 자체 구현이 필요할 수 있다.
- **비용 추정 없음** : 게이트웨이 구축·운영 비용은 산정하지 않았다.
- **Ⅳ·Ⅴ는 전적으로 자체 제안**이며 관계기관과 검증된 바 없다.
