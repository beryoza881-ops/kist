# 상호운용성 표준 채택 유인(인센티브) 설계 참고사례집

> 조사일: 2026-09-08 · **대상: 장비·SW 기업이 표준 API·드라이버를 구현하게 만드는 유인 설계**
> 관련 문서: [자율실험실_표준인증_조사.md](./자율실험실_표준인증_조사.md)
>
> **문서 성격**: §0~§5는 공개 출처가 있는 조사 결과. **§7(SDL 적용 제안)은 자체 제안이며 미공표 설계안이다.**

## 0. 문제의 성격 — 상호운용성 표준은 "닭과 달걀"이다

GS인증·NEP 같은 **품질·우수성 인증**과 상호운용성 표준은 인센티브 구조가 근본적으로 다르다.

| | 품질·우수성 인증 (GS, NEP) | 상호운용성 표준 (SiLA 2, OPC UA LADS) |
|---|---|---|
| 가치 발생 시점 | **인증받는 즉시** (조달 자격 획득) | **다른 참여자도 채택해야** 비로소 발생 |
| 혼자 지켰을 때 가치 | 있음 | **0** |
| 벤더의 판단 | "받으면 이득" | "**남들 다 하면** 하겠다" |

이것이 실제로 발목을 잡고 있다 — SiLA 2와 OPC UA LADS 모두 **실제 네이티브 지원 기업은 수십 개 수준**이고, 대다수 상용 장비는 둘 중 무엇도 지원하지 않는다.

따라서 상호운용성 표준의 인센티브는 "우수함을 인증해 주는 것"이 아니라 다음 두 축이어야 한다:

- **축 A. 구현 비용을 0에 가깝게** — 벤더가 "해볼까?" 하는 문턱을 없앤다
- **축 B. 수요를 확정적으로 만들어준다** — "누가 사주나?"에 답한다

그리고 보조적으로 **축 C. 구현·시험 비용 직접 보조**.

## 1. 【축 A】 구현 비용을 0으로 — ① 무상 오픈소스 SDK·레퍼런스 구현

### SiLA 2의 전략 — "문서 대신 동작하는 코드를 준다"

- **공식 레퍼런스 구현**: **Java, Python**을 비롯해 **C#, C++, JavaScript** — 통합업체가 실제로 쓰는 주요 언어를 모두 커버
- 기존 Feature 정의로부터 **타입 안전한 클라이언트를 자동 생성**. 장비 벤더 쪽에서는 **서버(Feature Provider) 구현을 프레임워크가 지원**
- **Tecan SiLA2 SDK** — **BSD-3 라이선스, 로열티 프리 오픈소스**. 장비 제조사(Tecan)가 직접 만들어 업계에 공개
- **UniteLabs Connector Development Kit (CDK)** — Python 레퍼런스 구현 기반의 커넥터 개발 프레임워크, 오픈소스
- **CETONI SDK for SiLA 2** — 자사 장비용 SiLA 서버를 오픈소스로 공개. 제공 콘솔 스크립트로 즉시 구동하고, 그 위에 자체 애플리케이션을 얹을 수 있음
- **SiLA Browser** — 무상 GUI 클라이언트. 벤더가 자기 구현을 즉시 눈으로 검증

> **설계상 배울 점**
> 벤더가 표준 문서를 읽고 밑바닥부터 구현하는 게 아니라, **동작하는 코드를 받아 자기 장비에 맞추기만** 하면 된다. 진입장벽의 대부분이 여기서 사라진다.
> 특히 **장비 제조사(Tecan, CETONI)가 자사 SDK를 오픈소스화**해 생태계에 기여한 구조가 핵심이다 — 표준화 기구가 아니라 **선도 벤더가 레퍼런스를 공급**했다.

## 2. 【축 A】 구현 비용을 0으로 — ② 무상 적합성 시험도구

### OPC Foundation의 UACTT

- **UA Compliance Test Tool(UACTT)** — OPC Foundation **법인회원은 무상 다운로드**
- 용도: OPC UA Client·Server 제품의 규격 적합성 시험. **개발·QA 워크플로에 통합**되어 수작업을 줄이고, **적합성 문제를 개발 초기에 잡아내며**, 공식 인증·상호운용성 시험 준비를 지원
- OPC UA FX 기능 시험을 포함해 **350개 이상의 테스트 스크립트** 보유

### open62541 — 오픈소스에서 인증까지의 경로 실증

- **open62541** (MPL 2.0 오픈소스 OPC UA 구현)의 예제 서버가 실제로 OPC Foundation의 **'Standard Server 2017 Profile' 인증을 획득**
- OPC Foundation 적합성 시험도구를 open62541 예제 서버에 돌리는 설정이 공개 저장소로 제공됨

> **설계상 배울 점**
> "인증 신청 → 탈락 → 재시험"의 비용과 불확실성이 벤더에게는 가장 큰 심리적 장벽이다. **무상 시험도구로 스스로 미리 통과 여부를 확인할 수 있게** 해주면 이 장벽이 사라진다.
> 그리고 **오픈소스 구현이 실제로 공식 인증을 통과했다는 사실 자체**가 강력한 마케팅이다 — "무료로 시작해서 인증까지 갈 수 있다"는 증거.

## 3. 【축 A】 구현 비용을 0으로 — ③ 플러그페스트 / 상호운용성 워크숍

### OPC Interoperability Workshop (IOP)

- **연 1회씩 일본·유럽·북미**에서 개최, **OPC Foundation 법인회원 무료 참가**
- 성격: *"제품의 상호운용성을 시험하고 **시장 출시 전에 인증을 준비하는** 바로 그 행사"*. 여러 벤더의 제품을 한자리에 모아 실제로 붙여본다
- 2025년부터 표준 OPC UA IOP에 **OPC UA FX Plugfest를 결합**해 운영

> **설계상 배울 점**
> 상호운용성은 문서로 보증되지 않고 **실제로 붙여봐야** 확인된다. 벤더가 개별 파트너십을 하나씩 맺어 1:1 통합시험을 하려면 비용이 폭발하지만, **플러그페스트는 이를 N:N으로 한 번에** 끝내준다.
> 무료 참가로 만들어 놓으면 벤더 입장에서 참가 자체가 이득이므로, **표준 채택의 실질적 온보딩 창구**가 된다.

## 4. 【축 B】 수요를 확정 — ① 규제 인증기준에 표준 API를 넣는다 (미국 ONC)

**세계에서 상호운용성 API 채택을 가장 성공적으로 강제한 사례.**

- 근거: **21st Century Cures Act**
- 방법: ONC(현 ASTP/ONC)가 Health IT 인증 프로그램에 **"standardized API for patient and population services"** 인증기준을 신설하고, **HL7 FHIR Release 4** 사용을 요구
- **2023년 1월 1일부터 인증 EHR 사용자는 표준 FHIR API를 갖추고** 승인된 파트너 및 환자와 정보를 교환할 수 있어야 함
- 병행 장치: **정보차단(information blocking) 금지** — EHR·API 기술이 *"특별한 노력 없이(without special effort)"* 실제로 접근 가능해야 한다는 요건. 커버되는 모든 주체가 전자건강정보 전체를 승인된 상대에게 제공해야 함
- 환자는 API로 자신의 전자건강정보 전부에 **무상** 접근

> **설계상 배울 점 (핵심)**
> 정부가 벤더에게 "이 API를 구현하라"고 직접 명령하지 않았다. **"인증받은 제품만 시장에서 통용되게" 만들고, 그 인증기준 안에 표준 API를 넣었다.**
> 그리고 **"구현했다고 주장만 하는 것"을 막는 장치(정보차단 금지)를 함께 뒀다** — 형식적 준수를 봉쇄하는 이 두 번째 장치가 없었으면 실패했을 것이다.

## 5. 【축 B】 수요를 확정 — ② 벤더가 아니라 **구매자**에게 돈을 건다 (국내 EMR 인증제)

**ONC 모델의 국내판이자, SDL에 가장 잘 맞는 구조.**

- 제도: **전자의무기록(EMR)시스템 인증제**. 보건복지부장관이 EMR 시스템의 **표준 적합성**을 검증해 인증. 2020년 6월부터 **한국보건의료정보원**이 위탁 수행
- **효과 실측**: 인증 EMR을 사용하는 의료기관 **41개소 → 4,052개소 (2024년 12월 기준)**. **상급종합병원 47개 전부 인증 획득**
- **2주기 인증기준(2025.1.1 시행)**: 서로 다른 EMR 간 정보연계에 필요한 **의료정보 표준화·상호운용성 인증기준을 강화**. 동시에 유사지표를 통합·간소화해 의료기관 부담은 완화
- **인센티브 설계 — 여기가 핵심**
  - 2024년부터 **인증 여부에 따라 종합병원급 이상 의료기관이 인센티브(의료질평가 지원금)** 를 받도록 제도 개편
  - 종합병원급은 EMR 인증 취득 시 **의료 질 평가 가산점 0.7**

> **설계상 배울 점**
> **벤더를 강제하지 않았다. 수요처(병원)에게 돈을 걸었다.**
> 병원이 "인증 EMR을 써야 지원금을 받는다"가 되면, EMR 업체는 아무도 시키지 않아도 인증을 받으러 온다. 4년 만에 41 → 4,052개소라는 증가는 이 구조가 작동했다는 증거다.
> 자율실험실도 마찬가지다 — **장비회사를 설득하는 것보다, 장비를 사는 대학·출연연에 유인을 거는 쪽이 훨씬 빠르다.**

## 5-1. 【축 B】 수요를 확정 — ③ "표준을 쓰면 특허가 안전해진다" (Bluetooth SIG)

유인의 방향을 뒤집은 사례. 표준 준수의 **대가를 받는 게 아니라 권리를 준다.**

- Bluetooth 기술을 제품에 넣으려면 **SIG 회원 가입이 필수**이며, **Adopter 회원 가입은 무료**
- 회원이 되면:
  - **회원 상호 간, Bluetooth에 "필수적인" 특허의 상호실시권(reciprocal license)**
  - **Bluetooth 워드마크·로고 사용권**
- 대신 **모든 제품은 판매·유통 전 Qualification 절차를 완료**해야 상표를 쓸 수 있음
- 비용 구조: **가입 무료, 제품 등재(Declaration) 시점에만 $4,000~8,000**

> **설계상 배울 점**
> "표준을 지키는 부담"이 아니라 **"표준을 쓰면 남의 특허를 안전하게 쓸 수 있는 권리"** 로 프레이밍했다.
> 그리고 **진입은 공짜, 상용화 시점에만 과금** — 개발 단계 벤더에게 비용이 0이라 일단 붙게 만든다.

## 6. 【축 C】 구현·시험 비용 직접 보조 — 국내에 이미 있는 제도

새 사업을 만들 필요 없이 **기존 지원사업의 대상 목록에 추가**하면 되는 항목들.

- **해외규격인증 획득 지원사업** (중기부 / 중소기업수출지원센터)
  - 수출 대상국이 요구하는 규격인증의 **인증·시험·컨설팅 비용 일부 지원**
  - 지원율: 전년도 매출 규모에 따라 **50~70%**
  - 한도: **기업당 최대 1억원** (의료기기 분야는 **최대 1.5억원**)
  - 지원 대상 인증: **총 572개** (EU CE, 미국 NRTL/UL, 중국 NMPA 등)
- **중소기업 우수제품 전파인증 시험비용 지원사업** — 적합성평가(적합인증·적합등록) 시험비용 지원

> **설계상 배울 점**
> OPC UA LADS·SiLA 2 적합성 시험 수수료는 **이미 존재하는 572개 지원대상 목록에 항목을 추가하는 것**만으로 보조가 가능하다. 예산 신규 확보보다 훨씬 빠른 경로.

## 7. 정리 — 벤더가 던지는 질문과 그 답

| 벤더의 질문 | 답이 되는 장치 | 사례 |
|---|---|---|
| "구현하는 데 얼마나 드나?" | 무상 오픈소스 SDK·레퍼런스 구현(5개 언어), 클라이언트 자동생성 | SiLA 2 공식 구현 / Tecan SDK(BSD-3) / UniteLabs CDK / CETONI |
| "인증 떨어지면 어쩌나?" | 무상 적합성 시험도구로 사전 자가검증 | OPC UACTT (법인회원 무상, 350+ 스크립트) |
| "오픈소스로 시작해도 되나?" | 오픈소스 구현이 실제로 공식 인증 통과 | open62541 → Standard Server 2017 Profile 인증 |
| "다른 회사 장비랑 진짜 붙나?" | 플러그페스트 무료 참가 | OPC IOP (일본·유럽·북미 연 1회) |
| **"그래서 누가 사주나?"** | **구매자에게 인센티브 → 수요 확정** | **EMR 인증제 (의료질평가 가산점 0.7 → 41개소→4,052개소)** |
| "안 하면 어떻게 되나?" | 규제 인증기준에 표준 API 편입 + 형식적 준수 봉쇄 | ONC FHIR API(2023.1.1~) + 정보차단 금지 |
| "특허 리스크는?" | 회원 상호 특허 실시권 | Bluetooth SIG (Adopter 가입 무료) |
| "시험비가 부담된다" | 인증 취득 비용 50~70% 보조 | 해외규격인증 획득 지원사업 (최대 1억) |

## 8. 〈자체 제안 — 미공표〉 SDL 상호운용성 표준에 적용하면

> 아래는 §0~§7 조사 결과에서 도출한 제안이며, 어떤 기관도 발표한 바 없다.

### 8-1. 단계별 실행안

**1단계 — 공급 마찰 제거 (레퍼런스를 공공이 공급)**
국가 예산으로 **국산 장비군별 SiLA 2 / OPC UA LADS 레퍼런스 드라이버를 오픈소스로 개발·공개**한다. 기초지원연·기계연 등이 보유 장비 라인업을 대상으로 수행.
→ Tecan·CETONI가 자사 SDK를 오픈소스화해 생태계를 연 역할을, **국내에서는 공공연구기관이 대행**한다. 중소 장비기업은 이 코드를 가져다 자사 장비에 맞추기만 하면 된다.

**2단계 — 사전검증 환경 제공**
**국가 SDL 상호운용성 테스트베드** 구축 + **적합성 시험도구 무상 배포**. 연 1회 **국내 플러그페스트** 개최(협의체 3개 분과 합동 — 장비기업·출연연·수요기업이 한자리에서 실제 연동 시험).

**3단계 — 수요 확정 (가장 중요, EMR 인증제 모델)**
벤더를 강제하지 않는다. 대신:
- 자율실험실 국가사업(AI-네이티브 첨단바이오 자율실험실 등)의 **장비 구매 사양서에 표준 인터페이스 지원을 요건화**
- 표준 지원 장비를 도입한 기관에 **과제 평가 가점 / 장비 구축비 지원 우대**
→ 수요가 확정되면 벤더는 시키지 않아도 구현한다.

**4단계 — 시험비 보조**
OPC UA LADS·SiLA 2 적합성 시험 수수료를 **해외규격인증 획득 지원사업의 지원대상 인증 목록(현재 572개)에 추가** 요청.

**5단계 — 규제 편입 (장기, ONC 모델)**
국가연구시설·장비 관리 관련 지침 등에 **표준 API 지원을 국가 R&D 예산으로 구매하는 실험장비의 요건**으로 반영. 동시에 **형식적 준수를 막는 장치**(ONC의 정보차단 금지에 해당하는 것 — 예: 적합성 시험 통과 결과 공개 의무)를 함께 설계.

### 8-2. 반드시 피해야 할 함정

1. **국제표준을 대체하는 독자 KS를 만들지 말 것.** SiLA/LADS와 별개의 한국 표준을 만들면 벤더는 구현 부담이 2배가 되어 오히려 아무것도 안 한다. **국제표준 채택 + 국내 프로파일·적합성 시험** 구조로 가야 한다.
2. **"표준 제정"에서 멈추지 말 것.** 표준 문서만 만들고 SDK·시험도구·플러그페스트가 없으면 채택되지 않는다. §1~§3이 §0의 축 A 전부다.
3. **수요 없이 공급만 밀지 말 것.** 3단계(구매 사양서 요건화)가 없으면 1~2단계에 쓴 예산이 회수되지 않는다. **EMR 인증제가 4년 만에 100배 확산된 이유는 SDK가 좋아서가 아니라 병원에 지원금이 걸려서다.**

### 8-3. 홍보 화법 예시 (벤더 대상)

- **"드라이버는 저희가 이미 만들어 뒀습니다"** — 오픈소스 레퍼런스 공급
- **"인증 전에 통과 여부를 직접 확인해 보실 수 있습니다"** — 무상 시험도구
- **"국가사업 장비 사양서에 이 표준이 들어갑니다"** — 수요 확정 (가장 설득력 있음)
- **"시험비의 최대 70%, 1억까지 지원됩니다"** — 비용 보조
